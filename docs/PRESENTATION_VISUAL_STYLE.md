# 演讲演示视觉观察

本文用于记录从横版 1920 × 1080 或竖版 1080 × 1920 的实际演讲演示和用户反馈中逐步形成的视觉观察、候选偏好与参考方法。

当前只记录了少量已确认的演示方法，尚未形成固定视觉模板。不要预先套用 B-roll 的构图、动画或节奏，也不要把一次演示采用的具体风格自动推广到后续作品。

本文不保存具体演示方案，也不替代实际作品数据。根本事实以 [AGENTS.md](../AGENTS.md) 为准，制作步骤见[演讲演示 Skill](../.agents/skills/presentation-production/SKILL.md)；讨论中形成的新偏好先按 [project-memory Skill](../.agents/skills/project-memory/SKILL.md) 提请确认，确认后再写入本文。

## 当前观察

### 分页服务注意力，而不是控制页数

- 2026-09-15：一页对应一个最小、清晰且完整的注意力焦点。分页不以页数更少为目标，也不按口播字数机械切割。
- 2026-09-15：当论证进入新的观察对象、判断层次或视觉状态时，应翻页；复杂案例可以拆成多页，让每个教学点都有独立画面和演讲提示。
- 2026-09-15：必须依靠回环形成效果的完整故事、对比或反转，应优先在同一页通过页内变化完成，避免翻页破坏因果关系。

### 页面同时服务观众与演讲者

- 2026-09-15：页面既要引导观众当下看什么，也要给演讲者提供清晰的内容提示。过度合并会让同一画面停留过久、造成视觉疲劳，也会削弱口播提示。
- 2026-09-15：连续页面之间应有明确的注意力变化；不能只因版式不同而翻页，也不能让一个页面承担多个需要分别记忆和解释的重点。

### 画面不复述口播

- 2026-09-15：画面不把口播稿改写成大段文字或项目符号，而应选择最能引领注意力的对象、关系、变化、对比或视觉隐喻。
- 2026-09-15：屏幕只保留观众当前需要识别和记住的信息。完整解释由演讲者提供，画面负责建立直觉、维持方向并强化结论。

## 实验与结果

- 2026-09-15：在《从 LLM 到数字员工》演示规划中，将完整周报故事拆成多页会削弱“三句话 → 一千字 → 三句话”的回环和反转；改为同页用页内变化表达后，主题更完整。

## 已否决或被替代

- 2026-09-15：否决为了减少页面数量，将整条时间线、完整复杂案例或多层方法论强行合并到少量页面。一个大主题内部若包含多个独立注意力焦点，仍应拆页。
