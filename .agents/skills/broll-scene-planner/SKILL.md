# B-roll 场景划分

本 Skill 只回答“哪些字幕组成一个场景”。不设计构图，不选择动画方式，也不生成 Scene JSON。

所有 pnpm 命令从工作区根目录执行。`projects/` 路径相对于 `app/`。

## 输入与产物

- 时间源：`projects/<project-id>/source.srt`
- 可选语义参考：用户提供的口播稿
- 审查文件：`projects/<project-id>/scene-plan.md`

不要修改 `source.srt`。口播稿与 SRT 不一致时，用口播稿理解章节和意图，用 SRT 确定实际时间。

## 工作步骤

1. 校验并完整阅读 SRT：

   ```bash
   pnpm validate:srt projects/<project-id>/source.srt
   ```

2. 从全文判断章节、主题转换、连续解释、录屏段落和适合留白的内容。
3. 将表达同一主题、能够由同一主画面承载的连续字幕归为一个场景。
4. 当核心主题或承载它的主画面明显变化时才开始新场景，不按句子机械切分。
5. 生成 `scene-plan.md`，在完整字幕的每个场景结束位置插入可见标记：

   ```text
   [场景 01｜Cue 1–8｜场景主题｜结束]
   ```

6. 用户知道但 SRT 中没有的过场标题，按用户指定的位置插入：

   ```text
   [过场标题｜Cue 36–38｜标题文字]
   ```

7. 停止并请用户审查。用户可以合并、拆分、改名或补充过场标题。

首次划分时，标记只包含编号、Cue 范围和主题，不提前写画面设计。录屏和留白也使用相同标记保留准确范围，具体形式由 Designer 写入画面描述。不要生成 Scene JSON 或另一份场景表。

## 时间规则

- 标记必须放在明确的 Cue 边界，并记录每个场景覆盖的首尾 Cue。
- Scene 起点使用首个 Cue 的起始时间；首场景需要与音频起点对齐时可以从第 0 帧开始。
- 场景按时间排列且不能重叠；字幕内容都归入明确场景，录屏或留白场景由 Builder 生成透明时间段，只有字幕之间没有内容的时间可以留空。
- 过场标题必须占用明确的 Cue 范围，不能只写插入位置或创建没有时长的场景；口播稿中的文字不能代替 SRT 时间。

## 完成条件

- 已阅读完整 SRT，而不是只分析局部字幕。
- 场景边界、主题和过场位置都能在 `scene-plan.md` 中直接审查。
- 每个场景只承载一个连续主题，没有把多个明显不同的内容强塞进同一场景。
- 用户确认划分后，再交给 [Designer](../broll-scene-designer/SKILL.md)。
