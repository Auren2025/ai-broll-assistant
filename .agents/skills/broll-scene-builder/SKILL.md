# B-roll 场景生成

本 Skill 负责把获批方案实际落地。不得重新解释主题、改换表达方式或调整场景边界。

所有 pnpm 命令从工作区根目录执行。`projects/`、`src/` 等路径相对于 `app/`。

## 输入

- 已获批的 `projects/<project-id>/scene-plan.md`
- `source.srt`、音频和已有项目数据
- `docs/BROLL_VISUAL_STYLE.md`
- `src/domain/` 下的当前 Schema
- 项目 `assets/` 中的实际素材

## 工作步骤

1. 确认目标场景、画布版本和两次用户审查已经完成，批量写入前关闭编辑器。
2. 按获批边界创建或更新 Project / Scene JSON；新项目需要替换 scaffold 生成的占位场景。
3. 严格按照 `画面设计` 生成图层、位置、尺寸、样式和动画。
4. 对未提供的必要图片创建 `src: null` 占位，并添加清楚的可见素材提示。
5. 运行：

   ```bash
   pnpm validate:project projects/<project-id>
   ```

6. 用编辑器预览检查单个场景的开场、关键变化和最终画面；用 Remotion Studio 检查完整时间线、音频对齐、透明区间和相邻衔接。修改后重新校验，并说明实际检查了哪些内容。
7. 请用户审查实际生成的完整草稿，只修改反馈涉及的场景。

## 实现边界

- Builder 可决定坐标、间距、具体字号、颜色值和动画参数。
- 如果落地需要改变主要构图、场景形式或信息顺序，停止并退回 Designer 与用户确认。
- 录屏段落和有意留白使用空图层 Scene 保留获批时间；录屏素材及最终合成不属于本应用。
- 不增加、删除、合并、拆分或重新计时场景。
- 不修改无关场景，不覆盖有效人工内容，不编造素材路径。
- 项目和场景 ID 只使用字母、数字、下划线和连字符。
- 一个项目只生成一个方向；画布必须是横版 1920 × 1080 或竖版 1080 × 1920。
- 使用当前支持的图层和动画，不写 Fabric 私有数据或逐帧结果。

## 素材与成品

- 实际素材只能引用项目 `assets/` 下已确认存在的文件。
- 素材占位的完整要求写入 Image `name`；可见提示使用独立顶层 Text，放在占位图附近且不与图片成组。
- 替换素材时保留获批布局和动画，并删除对应制作提示。
- 含空图片或制作提示的场景只能标记为草稿。
- 用户无法提供所需素材时退回 Designer 调整方案，不静默替换设计。
- Planner 必须把末尾录屏或留白范围列为获批场景；Builder 用空图层实现它并覆盖到 `source.srt` 最后一个 Cue 的结束位置，不临时新增计划外场景。
- 数据校验和视觉检查分别报告；无法预览时明确说明。
- 完成草稿审查后返回 [B-roll 制作调度](../broll-production/SKILL.md)；只有用户明确要求时才渲染视频。
