# B-roll 制作调度

本 Skill 只负责阶段调度和最终交付，不代替各阶段做专业决定。

所有 pnpm 命令从工作区根目录执行。命令参数中的 `projects/`、`src/` 等路径相对于 `app/`。

## 标准流程

```text
用户准备 SRT 和音频
→ Planner 生成 scene-plan.md 的场景划分
→ 用户审查边界、主题和过场标题
→ Designer 补充可直接想象的画面设计
→ 用户审查画面方案
→ Builder 批量生成 Scene JSON
→ 校验和视觉检查
→ 用户审查实际生成的完整草稿
→ 补充素材并修改反馈场景
→ 用户要求时渲染视频
```

两次审查都必须完成，除非用户明确要求跳过。不要因用户提供了完整输入就默认获得批量生成授权。

## 调度规则

- 新建项目、划分字幕、修改边界或补充过场标题：使用 [Planner](../broll-scene-planner/SKILL.md)。
- 为已确认场景构思画面、录屏方式或口播节奏：使用 [Designer](../broll-scene-designer/SKILL.md)。
- 将获批方案写成图层和动画、替换素材或做视觉检查：使用 [Builder](../broll-scene-builder/SKILL.md)。
- 只修改某一阶段时直接使用对应 Skill，不重复前置阶段。
- 讨论形成可复用结论时，使用 [project-memory](../project-memory/SKILL.md) 提请用户确认后再保存。

## 输入检查

- 用户负责在项目外准备口播、录音和 SRT；本流程从文件已放入项目后开始。
- 继续已有项目时先读取其 `MEMORY.md`；尚无 `project.json` 时运行 `pnpm scaffold <project-id>`。
- B-roll 的时间依据是 `source.srt`，音频用于预览和最终剪辑对齐。
- 进入规划前确认 SRT 有效、对应音频存在且 `audioFile` 指向正确文件。
- 可读取用户提供的口播稿补充章节和过场信息，但时间仍以 SRT 为准。
- `source.srt` 保持原样；场景划分和设计写入同项目的 `scene-plan.md`。
- 一个项目只保存一个画布版本；横版和竖版使用不同项目 ID，不能通过改尺寸覆盖另一个版本。
- 用户同时要求两个版本时，先确认两个项目 ID，再分别完成规划、设计、生成、检查和交付。
- 批量修改 JSON 前确认编辑器已关闭，并保护无关人工内容。

## 交付

- 草稿必须说明未替换素材和未完成的视觉检查。
- 外部图片和产品录屏由用户准备；Builder 负责整理需求、导入图片和替换占位。
- 产品录屏和口播在应用外完成合成；本应用渲染的是与时间线对齐的静音透明 B-roll 画面。
- 数据校验与视觉检查分别报告，校验通过不代表画面已经合格。
- 只有用户明确要求时才执行 `pnpm render:project <project-id>`。
- 最终视频需要所有必要素材已替换，且不再显示制作提示文字。
- 完成重要审查或交付后，按记忆规则提出候选条目，不直接写入。
