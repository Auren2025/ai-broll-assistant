# B-roll 画面设计

本 Skill 把已确认的场景划分变成可讨论的画面方案，不生成图层或 Scene JSON。

## 输入

- 已获批的 `projects/<project-id>/scene-plan.md`
- 对应的 `source.srt`、音频和可选口播稿
- `docs/BROLL_VISUAL_STYLE.md`
- 项目已有素材和相关参考作品

## 工作步骤

1. 按场景阅读对应字幕和上下文，不能只看场景标题。
2. 判断这一段使用动画、产品录屏、过场标题还是有意留白。
3. 对需要制作的场景，在原标记下写一段 `画面设计：`。
4. 完成全部场景后停止，请用户审查；没有批准前不进入生成阶段。

## 描述要求

画面设计必须是一段能直接在脑中形成画面的自然语言，说明：

- 画面中具体出现什么；
- 元素位于左、中、右或上下什么位置；
- 开场时看到什么；
- 随口播如何出现、移动、替换或高亮；
- 最后停留在什么画面。

不要把设计拆成“类型、阅读顺序、画面变化”等抽象字段，也不要只写“突出重点、建立层级、依次强调”之类无法想象的术语。

示例：

```text
画面设计：在画面左、中、右水平排列 Planner、Designer 和 Builder。开场同时显示三个名称和连接关系；随着口播提到不同阶段，对应区域放大并高亮，其余两个降低亮度；最后恢复三个区域同时显示的完整流程。
```

需要图片或录屏时，把具体对象、画面范围和必须看清的内容写进同一段；只有需要用户另行准备文件时，才补充一行 `所需素材：`。

录屏方案还要写清录制对象、起止操作和对应 Cue 范围；录屏由用户在应用外准备，Builder 只保留透明时间位置。

## 边界

- 不修改用户已确认的场景边界和时间。
- 过场标题是否存在、显示什么文字和占用哪个 Cue 范围由 Planner 与用户决定；需要新增时退回 Planner。
- 横版 1920 × 1080 与竖版 1080 × 1920 分别设计，不直接复用固定坐标。
- 使用 Style 形成具体方案，不复制参考项目，也不把一种构图套给所有场景。
- Designer 决定主题表达、主要构图和信息变化；具体坐标、字号和动画参数交给 Builder。
- 用户确认全部画面设计后，交给 [Builder](../broll-scene-builder/SKILL.md) 批量生成。
